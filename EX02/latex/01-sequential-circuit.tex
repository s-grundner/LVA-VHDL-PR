\subsubsection{Counter-Architecture:}

The counter value is stored in a register. Each clock cycle, the register contents
are loaded with a the next, combinatorially determined value. The next value is either
the incremented counter value or $0$, if a synchronous reset strobe is set.

\subsubsection{Statemachine-Architecture}

The functionality of the statemachine is described by two processes: One
register process describes the clock and reset behaviour. Here, the state
variable is updated every clock cycle. Another combinatorial process
determines the next state. Here the counter period can be set by editing
the \lstinline{MAX_COUNT} constant.

\subsection{Simulation}

\textbf{Test-Bench}

Before the stimulus process a clock oscillation is emulated and a reset is
performed. To test the module implementations, two scenarios are tested:

\begin{itemize}
    \item Pressing the start button at different timestamps
    \item Performing a synchronous reset
\end{itemize}

\textbf{Start Button Stimulus}

A single start pulse triggers the statemachine:
\begin{center}
    \includegraphics[width=\textwidth]{images/SimP2_1.png}
\end{center}

Any further start button press have no effect during the \lstinline{WAIT} and the \lstinline{LED_ON} state.
\begin{center}
    \includegraphics[width=\textwidth]{images/SimP2_2.png}
\end{center}

\textbf{Reset Stimulus}

The waveform shows, that a synchronous reset during the \lstinline{WAIT} and \lstinline{LED_ON} cancels the blinking process of the led.

Because the outputs are purely dependent on the states themselves and not on any other inputs, the fsm is per definition a mealy machine.
